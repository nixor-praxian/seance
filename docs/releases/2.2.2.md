# 2.2.2 — display-change settle loop, and `seance reflow`

## Summary

Connecting a display produced several full reflows rather than one. The
watcher's display-change handler now waits for the display geometry to stop
changing before acting, and acts once on the shape that actually held. A new
`seance reflow off` disables the behaviour entirely for users who would rather
the watcher never touched window geometry on hotplug.

## Impact

Anyone running the watcher with more than one display. Connecting a single
external display was observed producing three consecutive full reflows, each
repositioning every active pane.

## Root cause

The handler was gated on `tick % 5` and, on detecting a change, slept a fixed
3 seconds, ran `organize`, and stored the signature it had captured *before*
the sleep:

```ts
if (screensSig && sig !== screensSig) {
  console.log("watch: display set changed — reorganizing in 3s");
  await new Promise((r) => setTimeout(r, 3000));
  await runOrganize();
}
screensSig = sig;      // the pre-sleep signature
```

Two defects. The sleep was a delay, not a settle detector: it never re-read
geometry to confirm the display set had stopped moving. And macOS emits several
transitions while negotiating a newly connected display — arrival, arrangement,
scaling — so each was seen as an independent change and got its own reflow.

The `tick % 5` gate is separately the anti-pattern `CLAUDE.md` documents: a tick
is one iteration of a loop performing `osascript` and `lsof` calls, so the gate
was minutes rather than the ten seconds it appeared to be, and detection latency
varied with load.

## Resolution

**Settle loop.** On detecting a change the watcher polls the signature every
750ms until it holds still for 3 seconds, with a 30-second cap, then runs one
`organize` against the settled shape and records that signature. If the display
set settles back to what it started as, nothing runs at all.

**Wall-clock gating.** The display check is now gated on elapsed milliseconds
rather than iteration count, so it happens every 2 seconds as documented.

**`seance reflow [on|off]`.** Persists `state.watchReflow`. With reflow off the
watcher still perceives panes, assigns and paints repo identity, and re-asserts
Claude Code's theme — it simply never repositions a window in response to a
display change. The watcher reloads state each pass, so the setting takes effect
without a restart.

## Known limitations

The display signature is still derived from `NSScreen.visibleFrame`, which
changes when the Dock is repositioned or toggles auto-hide. Such a change is
indistinguishable from a display change and will trigger a reflow. The fix is to
key the signature on `NSScreen.frame`, which describes the hardware rather than
the current Dock state; the JXA in `listScreens` already reads it and discards
it. Deferred to the display-set presets work, which needs the same stable
signature.

Reflow on hotplug remains unconditional when enabled: it re-derives a layout
from scratch rather than applying one previously saved for that display set.
That is what the presets work replaces; `seance reflow off` is the interim
answer.
