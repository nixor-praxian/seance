# 2.2.3 — a returning display arrangement is no longer re-derived

## Summary

Reconnecting to a familiar display setup reshuffled every pane. macOS had
already restored the windows to where they were — correctly — and the watcher
then discarded that and derived a fresh layout on top. The watcher now leaves a
display arrangement alone once it has laid it out, and re-tiles only for
arrangements it has not seen. `seance reflow` becomes a three-way setting.

## Impact

Anyone running the watcher who moves between the same display setups.
2.2.2's settle loop reduced one connection from several reflows to one, but one
unwanted reflow is still an unwanted reflow, and the returning-dock case is the
one where the reflow is always wrong.

## Root cause

The handler acted on any signature *change*:

```ts
if (screensSig && sig !== screensSig) { /* settle, then organize */ }
```

Going docked (A) → undocked (B) → docked (A) again, the return to A is a change
from B, so it reflowed. The 2.2.2 guard for "settled back to the previous shape"
only catches a signature bouncing *within a single settle window*; it cannot see
that A is a configuration already laid out earlier. It had fired zero times in
the log.

What made the result actively worse than a no-op is that macOS restores window
positions per display arrangement on its own, and does it well. The panes were
already right. The reflow replaced a correct restoration with a freshly derived
layout that had never existed before.

Confirmed in `watcher.log`: two `waiting for geometry to settle` events, one per
transition — the settle loop working — the second producing
`external.left 5x2` + `main 4x2` over windows macOS had already placed.

## Resolution

The watcher records the signature of every arrangement it lays out, plus the one
it boots into, in `state.knownDisplaySets` (derived, capped at 16). On a settled
change it now distinguishes three cases:

| case | action |
|---|---|
| settled back to the shape it just left | nothing |
| an arrangement already laid out | nothing — macOS's restore is the layout |
| a new arrangement | one organize, then remember it |

`seance reflow [always\|new\|off]` replaces the `on`/`off` boolean shipped in
2.2.2. `new` is the default and the behaviour above; `always` restores
re-tile-on-every-change; `off` never touches geometry. `on` is accepted as a
spelling of `new`, and a stored `watchReflow: false` migrates to `off` on load.

## Known limitations

The unplug direction is treated the same way, and the reasoning there is
weaker. Disconnecting a display leaves windows that lived on it to be moved by
macOS onto whatever remains, at their original sizes — which can overlap or
overhang. Once a laptop-only arrangement has been laid out once, seance will no
longer clean that up, on the assumption that macOS's restore is good in both
directions. That assumption is confirmed for reconnection and untested for
disconnection. If undocking starts leaving a mess, `seance reflow always` is the
escape hatch and this rule should become directional.

The signature still derives from `NSScreen.visibleFrame`, so toggling Dock
auto-hide reads as a display change. Carried over from 2.2.2; it now costs at
most one reflow the first time, since the resulting signature is then known.

## Verification

- `npm run typecheck` — clean.
- `npm test` — 184 tests across 8 files, all passing, including the default
  mode, all three settings, the retired `on` spelling, and the `watchReflow`
  migration.
- `dist/` rebuilt and the watcher restarted, which seeds the current
  arrangement so today's setup is protected immediately.
- **The behaviour itself is unverified against hardware.** It needs a physical
  disconnect and reconnect, with `watcher.log` showing
  `known display arrangement — leaving macOS's restore alone` in place of an
  `organized` line.
