# 2.3.0: repos keep their colour, and every screen gets used

## What you'll notice

**Your repos stop changing colour.** A busy pane could flip colour over and
over, and a repo could be recoloured just because a different repo happened to
be open next to it. Now a repo gets its colours once and keeps them: same theme, same
tint, next month as today.

**Two repos stop looking like the same dark grey.** Most dark themes turn out
to be the same near-black background wearing different accents. So every repo
also gets its own background tint, picked to stand apart from whatever is open
beside it. If two open repos still end up sharing a theme, seance shades one of
them on screen, without touching either repo's saved colour.

**`arrange` fills all your screens.** With externals stacked in a grid, a whole
column of screens could sit empty while panes piled onto one. Every connected display takes its share now.

**A pin means that exact screen.** `seance place <repo> --screen <n>`
remembers the display itself, so it can reach a fourth or fifth one. Unplug it
and the repo falls back to the pin's role until it comes back. A screen holding
a pinned repo is kept for pinned repos.

**Replugging a dock doesn't cram everything onto two screens.** Screens wake up
one or two at a time, and the watcher used to tile onto whichever ones showed
up first. It now waits rather than squeeze onto fewer displays.

**New: `seance arrange --in-place`** tiles each display where its panes already
are, and moves nothing between screens.

**`seance --version` tells the truth.** It had said `0.0.1` since day one.

## Do I need to do anything?

Restart the watcher so it runs the new code: `seance watch --install`. If it
was installed from a temporary checkout, it now refuses and says so; install
it from your real clone.

That's it. Colours you already have are kept. Repos without a tint get one the
next time they are painted, unless you've set a `seance background` for them,
which still wins.

## Under the hood

Why colours drifted, in four parts:

1. **A pane's repo was read from its newest process.** On a Claude Code pane
   that is usually a short-lived child (a Bash tool call, `caffeinate`, an MCP
   server). When it exited between `ps` and `lsof`, the pane looked like it
   lived in `home`. Identity now comes from the shell `login` started, folded
   to the git repo root; linked worktrees map to the repo that owns them.
   Session snapshots also record `claude` instead of whatever child was newest.
2. **A collision recoloured the loser permanently.** Assignment is write-once
   now: an existing repo never changes pair, and a new repo takes a pair no
   open repo is wearing, least-worn first.
3. **Different themes, same grey.** Most dark themes ship a near-black
   background. The new tint is chosen with hue weighted over lightness, since
   plain OKLab distance called black and near-black "different" and on screen
   they are not. The tint goes through the contrast guard like any background.
4. **The launchd watcher was running a deleted copy** from a temporary agent
   checkout, so fixes looked inert. `watch --install` now checks.

Display roles: the old code picked the two leftmost externals as left and
right. Two stacked screens share an x, so both roles landed in the same column.
Roles now take the nearest external on each side of the main display, and displays
beyond the three roles are labelled `display <n>` and remembered by UUID.

Placement checking: `setWindowBounds` now compares size as well as origin. A
window moved to another display could arrive at the right spot with its old
size and still be counted as placed.

## Known limitations

- Fixed colours mean a repo opened for the first time while every pair is in
  use shares a pair, distinguished by tint and shade rather than theme.
