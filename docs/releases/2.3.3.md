# 2.3.3: the Alfred palette and the watcher survive a Node upgrade

## What you'll notice

**`s` in Alfred keeps working after you upgrade Node.** Before, an nvm upgrade
could quietly break it: type `s arrange` and Alfred showed you folders with
"arrange" in the name, because the seance part never answered.

**The watcher comes back after a reboot.** Same cause. It kept running until
the next login, then couldn't start, and new panes stopped getting their
colours.

## Do I need to do anything?

Run these once, so both pick up the new launcher:

```bash
seance alfred install
seance watch --install
```

After a later Node upgrade, macOS may ask again for Accessibility permission,
since it sees the new `node` as a different program. Grant it and the watcher
goes back to moving windows.

## Under the hood

Both installs recorded `process.execPath`, the exact Node binary that ran
them. The Alfred workflow put that binary's directory on its `PATH`, and the
launchd plist ran that binary directly. nvm keeps each version in its own
directory and an upgrade can remove the old one, so the path pointed at
nothing. Alfred's script failed, and Alfred fell back to its normal search,
which looks a lot like the palette returning junk.

Now both call `bin/seance`, a few lines of shell that pick a Node each time
they run: the highest nvm version (by `sort -V`, so v22.23 beats v22.9), or
whatever `node` Homebrew or `/usr/local` provides. It then runs
`dist/cli.js` with `exec`, so the watcher process is still plain `node`.

A test runs the launcher with only `HOME` and launchd's bare `PATH`, against
three fake Node versions, and checks it picks the newest.
