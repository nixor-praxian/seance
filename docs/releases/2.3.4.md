# 2.3.4: `arrange` fills each display with columns

## What you'll notice

**Four panes means four columns.** `seance arrange` now lays out everything on
a display as one grid, columns first. Each pane gets its own full-height column
until another column would be narrower than `minPaneWidth` (384 points by
default). After that it starts a second row and balances the two, so 5 panes on
a display that fits 4 columns come out 3 + 2, not 4 + 1. A repo's panes still
sit next to each other, in reading order.

**No more mixed shapes on one screen.** Before, `arrange` cut each display into
one block per repo and laid each block out on its own. Two repos with two panes
each plus a third with one could give the first repo two full-height columns,
the second a half-height row, and the third whatever was left.

**Saved grids stay home.** A grid you set with `place` (say `place mercury 4x1
--screen 2`) now applies only on that display. If the display is unplugged
and mercury ends up on another display, it gets the normal column layout. Before,
the 4x1 came along, and two mercury panes on a 1728-point-wide screen became
two 345-point slivers, under the readable minimum.

**`organize 5x1` with six panes works.** It used to stop with "won't fit 5x1,
need at least 6 cells". A grid too small for the panes now grows along its
long side: `5x1` becomes `6x1`, `1x4` with five panes becomes `1x5`. The
`place` item in Alfred already grew a grid that was too small, but by adding
rows (`4x1` with five panes was `4x2`), and `seance place` typed in a terminal
refused it outright. Both now grow the same way as `organize`.

**Tabs don't leave holes.** A Ghostty window with two tabs has two shells but
only one window you can see. seance counted both as panes, gave each a column,
and the background tab's column stayed empty. Now a shell with no window of
its own on the current Space is left out of the layout, and `arrange` or
`organize` prints which repo it skipped.

**You choose how narrow a column can get.** `seance min-width` shows the
narrowest column seance will make and how many columns that gives each
display. `seance min-width 288` lowers it, so a 1728-point screen takes 6
columns before wrapping instead of 4.

## Do I need to do anything?

No. Run `seance arrange` and you get the new layout. If you'd rather have more,
narrower columns than a second row, lower `seance min-width`.

## Under the hood

The old rule picked, per repo block, the grid whose panes came closest to a
9:16 aspect. With a single repo that already gave columns (4 panes on a
1728-point display were 4x1). The trouble was the blocks: with several repos
the display was split by pane count first, and each block's grid was chosen
independently, so neighbouring repos could get unrelated shapes.

The new rule is one line of arithmetic: `cols = min(n, floor(width / 384))`,
`rows = ceil(n / cols)`, then `cols = ceil(n / rows)` to balance. Cells are
handed out to repos in order, so a repo can wrap from the end of one row to
the start of the next.

Pins: a rule's grid is used only when the display being laid out is the rule's
own (its saved display UUID, or its role's display when it has none), and the
repo has that display to itself. The pin used to be applied wherever the repo
landed, even when the result was flagged as unreadable.

Tabs: macOS lists only the front tab of a tab group as a window, so the
title check seance uses to match a shell to its window never finds a
background tab. An unmatched shell used to count as active, on the theory that
it had only lost a timing race. That theory now applies only when there are at
least as many windows as shells. With fewer windows, an unmatched shell (after
a second try) has no window here: it's a background tab or on another Space,
and gets no cell. A window on another Space is skipped too, where before
`organize` tried to pull it over. `seance gather` is the way to bring those back.

One effect on portrait displays: two panes on a 1080-point-wide portrait screen
are now two columns, not two stacked rows.
